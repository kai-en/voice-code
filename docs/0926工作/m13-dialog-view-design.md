# M13 对话流水视图（dialog.bat）设计

> 2026-09-26。用户口径：直播时听不清 oc2 说了什么，就 glance 一下文字。只要"你 / 助手"双方流水，走 WS，`dialog.bat` 打到 console（照 log.bat 的用法）。**不是排障工具**（排障用 log.bat + 日志）。不用 opencode web 端——直播时手上没空操作网页。

## 1. 关键结论：src/ 零改动，数据早就在链上

M11 控制台已经在广播两样东西，正好就是这个需求的全部原料：

| 需要的行 | 现成的帧 | 全文？ |
|---|---|---|
| `你：…` | `{"t":"ev","kind":"AsrText","d":{"text":…}}`（打字问是 `kind":"TextIn"`） | ✅ 全文（`frames.pick` 截到 2000 字，够） |
| `助手：…` | `{"t":"speak","text":…}` —— 每句实际进口播的完整文本 | ✅ 全文 |

注意区分：`_brief` 的 24/16 字截断**只作用于日志**（那是 T-E 的事），WS 帧里是全文。所以本需求**不需要新协议、不需要新帧类型、不需要改 server**。

## 2. 交付物与行数预算

| 文件 | 内容 | 行数 |
|---|---|---|
| `src/console/dialog.py` | 连 `ws://127.0.0.1:8765/`；逐帧打印：`ev.kind in (AsrText,TextIn)` → `你：<text>`；`t=="speak"` → `助手：<text>`；其它帧忽略 | **~18** |
| `dialog.bat` | `@echo off` + `cd /d %~dp0` + 一行调用 python（照 `log.bat` 写法） | **~5** |
| `src/` 任何既有文件 | 无（server/frames/core 一行不改） | 0 |
| **合计** | | **~23 行**（上限 30） |

行为细节（都含在上面 23 行内，不额外加行）：
- 连不上 → 打一行「助手没起来（先 run.bat）」退出，不自动重试（重试=膨胀）。
- 一句一行、按序输出，`\n` 压成空格；不加时间戳、不加颜色、不分轮次、不缓存历史。
- Ctrl-C 退出，进程随终端死（与 run.bat 的隐藏 daemon 无关，dialog 只是观察者）。

## 3. 我砍掉的"自己膨胀出来的功能"（反思清单）

| 诱惑 | 为什么砍 |
|---|---|
| 新增 `{"t":"dialog","who":…}` 帧类型 | server 已把 AsrText/speak 原样镜像，再加一种帧就是同一份数据两条路径，还得防两条不一致 |
| 主进程侧维护"对话历史"并支持新客户端回放 | 观察者随时可关可开，丢掉的行不追；要做就得加环形缓冲 + 游标协议，纯膨胀 |
| 按轮分组（一问一答配对）、时间戳、ANSI 颜色 | 需求是"听不清时看一眼"，一句一行最省力；分组要先定义"轮边界"，又是一堆状态 |
| 合并同一轮的多条 AsrText（VAD 一句一个事件） | 分开显示恰好反映 ASR 真实切分，对"我没说清吗"这个排障旁证有用；合并反而丢信息 |
| 用 `OcTurnDone.text` 显示"模型全文" | 那是**没出口播**的内容也算；本视图要的是"助手说了什么"，`speak` 才是真值 |
| HTML 页面 / 浏览器看 | 明确不用（手上没空操作网页），且 M11 已定"不 serve HTML" |
| `--follow`/`--tail`/写文件/多设备选择 | 与 log.bat 重复，需求没要 |
| 自动重连 | 直播场景里断线=助手本身出事了，该看 log.bat，不是让 dialog 静默兜住 |

## 4. 验收

- 自动（1 条，进 `tests/test_m11_console.py`，复用现成的 fake orch + 真 serve）：喂 `AsrText` + `speak` 两类帧，断言 dialog 客户端的投影函数输出恰为两行 `你：…` / `助手：…`。为此把投影逻辑写成纯函数 `render(frame) -> str|None`（+3 行，仍在预算内）。
- 人工（并入 H4′）：`run.bat` → 另开窗口 `dialog.bat` → 唤醒问一句 → 屏幕上先出「你：…」再逐句出「助手：…」，与耳朵听到的内容逐句一致；再说一句打断，新句照常出现。

偏差来源（逐条）：
1. **落点变了**：从 `scripts/dialog_view.py` 改成 `src/console/dialog.py`。原因：`scripts/` 不在 pytest 的 `pythonpath=src` 里，测试就得写 `importlib` 三行样板；改到 `src/console/` 后 `from console.dialog import render` 直接可用。副作用：这 34 行进了 `src/` 业务代码账（M13 原计划 0 行）。
2. **注释与空行 10 行**：文件头 3 行（用途/设计文档指针/跑法）+ `render` 里 1 行"为什么取 speak 不取 OcTurnDone"（这是本设计唯一需要防遗忘的判断）+ 空行。
3. **失败提示写成 2 行**（含回显当前端口），为的是区分"助手没起来"与"端口不对"。这条我承认可以压成 1 行。
4. **纯逻辑其实 12 行**：`render` 8 行 + `_run` 4 行。也就是说需求本体仍然远小于 100 行红线，超的是包装。
